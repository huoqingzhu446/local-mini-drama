# 纸片工作室跨场景连续性与转场质量优化方案（Planner v9）

## 1. 背景与问题定义

当前纸片工作室已经具备独立素材、接地点、地面区域、声音驱动画面时长和冻结快照能力，但多节拍分镜仍可能把不同地点或不同视觉世界编译到同一张背景上，再通过单个素材的透明度变化完成所谓“切换”。这种处理会产生以下系统性问题：

- 剧本已经发生地点变化，渲染树却只有一个环境底图。
- 新主体在一两帧内完全出现，形成视觉跳变。
- 主体的大位移被压缩到一帧，总位移门禁仍会误判为通过。
- 接触、字幕换句、新主体出现、军阵启动等语义事件挤在相邻帧。
- 证明流程只验证“画面发生变化”，没有验证变化是否连续、自然和符合场景语义。
- 自然化后处理只能改变缓动，不能修复错误的节拍边界或缺失的场景转场。

“巨鹿危城”是固定回归样本：城内粮袋与城外粮车属于两个视觉场景，Planner v8 却使用一张背景；字幕关键词“秦军补给”还错误命中第一句，使粮车的完整位移只剩一帧。

本方案不迁移渲染框架，继续使用现有 Remotion。所有运动必须由冻结快照、`useCurrentFrame()` 和明确帧区间确定，禁止依赖 CSS 动画、墙钟时间和非确定性随机数。

## 2. 目标

Planner v9 必须做到：

1. 区分同场景动作、同场景主体切换、机位变化、地点变化和时间跳跃。
2. 先形成视觉场景与节拍，再编译素材槽位和运动轨道。
3. 每次跨场景变化都有显式转场合同。
4. 转场操作完整场景组，而不是分别淡出、淡入单个素材。
5. 时间不足时延长画面或压缩非核心停留，绝不能把主要运动压成一两帧。
6. 逐帧检查速度、加速度、透明度、事件密度、接地和场景一致性。
7. 每个转场生成前、中、后证明帧，并在正式渲染与发布前重复门禁。
8. 音频和字幕为独立全局轨道，转场不能截断声音或把字幕甩出画面。
9. 地点变化需要独立环境底图；零调用模式只允许同一地点的虚拟机位变化。
10. 旧 Planner v8 快照继续可播放，但新生产与重新发布必须使用 v9。

## 3. 非目标

- 不引入实时物理引擎。
- 不使用 WebGL shader 作为必需能力；首版使用 Remotion 帧驱动的推移、叠化、模糊和程序化尘土。
- 不自动重新生成已经批准的角色或道具。
- 不在没有图片授权时自动生成第二张背景。
- 不用像素分割冒充任意背景的精确地形识别。

## 4. 总体链路

```text
剧本/旁白/字幕
  -> 视觉场景识别
  -> 视觉节拍分配
  -> 转场合同
  -> 场景素材槽位
  -> 场景组组合树
  -> 主体/场景/转场轨道
  -> 计划级连续性门禁
  -> 冻结快照
  -> 转场证明帧
  -> 像素连续性门禁
  -> 预览批准
  -> 正式渲染
  -> 发布前复检
```

## 5. 变化类型判定

### 5.1 `continuous_action`

同一地点、同一机位、同一主体的连续动作。例如人物从门口走到桌旁。保持连续轨迹，不创建场景转场。

### 5.2 `subject_change`

同一地点、同一视觉世界内更换关注主体。例如粮袋落地后同一条道路上的车辆进入。使用主体进入动画或焦点转移，背景保持连续。

### 5.3 `camera_change`

同一地点但机位、景别或关注区域明显变化。小幅变化使用虚拟机位推移；视角或遮挡关系变化过大时需要第二环境底图。

### 5.4 `location_change`

地点从室内到室外、城内到城外、营帐到战场等。必须使用两个视觉场景和两个环境家族，不允许只替换前景素材。

### 5.5 `time_jump`

叙事时间发生跳跃。使用淡黑、光线变化或时间提示；不得伪装成连续动作。

### 5.6 `explicit_hard_cut`

只有剧本明确要求快速蒙太奇、闪回、撞击切镜等情况才允许硬切，并记录 `hard_cut_reason`。时间不足不能自动降级为硬切。

## 7. 字幕与节拍对齐

关键词定位必须支持：

- `after_frame`
- `after_caption_key`
- `exclude_caption_keys`
- 精确短语优先于宽泛关键词
- 同一关键词重复时选择上一节拍之后的字幕
- 返回匹配字幕 key、边界和置信度

低置信度处理：

- 有可用安全比例时生成草案并提示人工确认。
- 无法保证节拍顺序时阻止确认蓝图。
- 不允许使用 `previous_frame + 1` 作为完整动作的最终兜底。

## 8. 时间分配规则

所有阈值以秒定义，再按 FPS 转为帧：

| 项目 | 默认值/下限 |
| --- | --- |
| 普通素材淡入 | 0.30 秒 |
| 普通素材淡出 | 0.30 秒 |
| 同场景主体交接 | 0.40–0.60 秒 |
| 推镜/甩镜 | 0.30–0.50 秒 |
| 尘土/模糊跨场景转场 | 0.50–0.80 秒 |
| 主体识别停留 | 至少 0.30 秒 |
| 地面车辆完整驶入 | 1.00–2.00 秒 |
| 接触事件到新主体半透明可见 | 至少 0.20 秒，除非显式匹配切镜 |
| 结尾停留 | 至少 0.80 秒 |

时间不足时按顺序处理：

1. 压缩非核心环境停留。
2. 压缩重复状态保持。
3. 保留主要动作、转场、字幕和结尾停留。
4. 仍不足时延长画面到完整声音之后。
5. 禁止压缩成一帧位移、两帧淡入或零长度节拍。

转场通过重叠相邻场景实现，不额外制造黑场；组合总时长始终以完整声音和结尾余量为准。

## 9. 场景组渲染结构

```text
root
├── scene_group_1
│   ├── registered_environment
│   ├── atmosphere
│   ├── characters
│   └── props
├── scene_group_2
│   ├── registered_environment
│   ├── atmosphere
│   ├── characters
│   └── props
├── transition_overlay
└── global_overlay
    ├── captions
    └── debug/proof
```

渲染规则：

- 转场对完整场景组应用统一进度。
- 旧场景使用加速离场缓动，新场景使用减速入场缓动。
- 出入方向与速度必须匹配。
- 字幕和音频位于全局层，不跟随场景移动。
- 程序化尘土使用帧和固定 seed，确保任意帧可复现。
- 场景组结束后保持确定性不可见，不依赖组件挂载时间。
- 旧 v3 快照没有场景合同，继续走旧递归渲染路径。

## 10. 转场策略

### 10.1 连续关系

同场景连续叙事使用轻微焦点转移或 0.4 秒交叉叠化。背景不得出现亮度骤变。

### 10.2 地点变化

战争场景默认使用 `dust_whip_pan`：

1. 旧场景在前 45% 时间内加速向转场方向离开并增加模糊。
2. 尘土覆盖在中点达到峰值，遮住两个背景的差异。
3. 新场景从反方向以匹配速度进入并逐渐清晰。
4. 转场结束后新主体才进入主要动作阶段。

### 10.3 时间跳跃

使用 `color_dip` 或 `soft_dissolve`，并在语义合同中记录时间变化。

### 10.4 硬切

只有 `hard_cut_allowed=true`、存在原因且门禁识别到声音重音或明确剧本指令时允许。

## 11. 素材和费用策略

### 11.1 正确模式

地点变化时为每个场景生成或复用独立背景。背景共享视觉风格、时代、天气、色调和媒介锚点，但分别审核场景内容。

### 11.2 零调用模式

只有同一地点、同一透视且背景存在足够裁切范围时，允许通过不同裁切和虚拟机位形成两个场景组。明确地点变化不能使用零调用模式冒充准确还原。

### 11.3 恢复顺序

1. 首先本地调整时间和转场，不重新生图。
2. 只有背景语义不匹配时才请求新图片授权。
3. 不自动重新生成已批准角色、道具和声音。
4. 新视频全部门禁通过后原子替换发布版本，旧文件保留为历史。

## 12. 计划级连续性门禁

门禁同时检查原始计划和自然化后的冻结计划。

### 12.1 结构门禁

- `location_change` 必须至少有两个视觉场景。
- 每个视觉场景必须存在对应环境家族和场景组。
- 每次跨场景变化必须有转场合同。
- 转场引用的场景、节拍和字幕必须存在。
- `start_frame < end_frame`，并满足最小时长。

### 12.2 运动门禁

通过逐帧有限差分计算：

- 最大速度。
- 最大加速度。
- 最大透明度斜率。
- 最大旋转和缩放斜率。
- 场景出入方向和中点速度误差。

默认 normal profile：

- 普通淡入至少 0.30 秒。
- 地面车辆横向速度不超过约 0.60 个画面宽度/秒。
- 相邻帧透明度跳变不超过 0.12（30fps 等效；其他 FPS 按秒换算）。
- 进入场景的主体不能首帧完整可见。

`impact` 和 `hard_cut` 允许更高阈值，但必须有显式合同和证明。

### 12.3 事件密度门禁

- 同一帧不得承载多个互不相关的主要事件。
- 接触事件、字幕换句、场景切换和新主体完全显现不能全部挤在相邻两帧。
- 若事件必须同步，必须声明 `matched_transition`。

### 12.4 接地和场景门禁

- 接地角色、道具和车辆继续服从接地点、允许区域和禁区规则。
- 场景切换后不能继承错误场景的地面区域。
- 每个场景的空间合同与对应背景一起冻结。

## 13. 渲染级证明

每个转场自动增加五个证明目标：

- `transition_pre`
- `transition_start`
- `transition_mid`
- `transition_end`
- `transition_post`

检查：

- 新主体是否大面积突然出现。
- 旧主体是否残留或重影。
- 主体质心是否瞬移。
- 中点是否产生黑帧、闪白或亮度突跳。
- 背景是否按合同变化。
- 出入光流方向是否连续。
- 字幕是否保持稳定可读。
- 新场景是否有足够识别停留。
- 接地对象是否继续落地。

证明失败应返回业务语言，例如：

> 第 2 场景的粮车在 0.07 秒内完全出现，低于 0.30 秒最低入场时长。

## 14. UI

蓝图编辑器新增“场景与转场时间轴”：

- 场景名称、地点、时间和环境素材。
- 视觉节拍、关联字幕和持续时间。
- 转场类型、方向、时长和是否需要新背景。
- 零调用/正确模式的差异。
- 低置信度和门禁警告。
- 只预览当前转场的入口。

证据面板新增：

- 转场前、中、后标签。
- 速度、透明度、亮度和场景变化指标。
- 可执行的修复说明。

必须覆盖：

- 重复字幕关键词不能倒回匹配。
- “人物转身”不误判为场景变化。

- 显式硬切通过，隐式硬切失败。
- 无旁白时按剧本节拍比例分配。
- 旁白变长时转场和结尾停留仍保留。
- 12/24/30/60fps 使用等效秒级阈值。
- 多次转场不重影。
- 转场字幕稳定。
- 转场后车辆接地。
- 旧快照可播放但不能以 v9 身份重新发布。
- “巨鹿危城”固定期望：两场景、两环境槽位、18 帧以上转场、粮车移动超过 30 帧、完整 12 秒画面。

## 18. 分阶段落地

### Phase A：立即安全门禁

- 顺序字幕匹配。
- 最小淡入/位移时长。
- 速度、透明度和事件密度门禁。
- 巨鹿危城不再产生一帧移动。

### Phase B：结构化场景转场

- Visual Scenes / Beats / Transition Contracts。
- 多环境家族和场景组组合树。
- Remotion 帧驱动的场景转场层。

### Phase C：证明与 UI

- 五阶段转场证明。
- 像素连续性指标。
- 蓝图时间轴和业务提示。

### Phase D：兼容与正式验收

- Planner v9。
- 历史快照兼容。
- 完整后端测试、前端测试和构建。
- 真实多场景分镜编译与渲染验收。

## 19. 完成标准

只有同时满足以下条件才算实现完成：

- 跨地点剧本被编译为多个场景组和独立环境槽位。
- 每个跨场景边界都有显式转场合同。
- 一帧瞬移、两帧淡入和隐式硬切会被门禁阻止。
- Remotion 使用帧驱动、可随机访问的确定性转场。
- 转场证明包含前、中、后证据和连续性指标。
- 发布前再次验证场景、运动、接地、声音和快照一致性。
- UI 能显示场景、节拍、转场、费用模式和失败原因。
- 旧成片不被破坏。
- 所列回归测试、完整后端测试、前端测试和构建全部通过。

## 20. 实施与验收记录（2026-07-31）

本方案已按 Planner v9 落地，验收结果如下：

- Blueprint、Semantic Contract、Motion Plan 和 Render Snapshot 已加入视觉场景、视觉节拍、转场合同及场景轨道；正式渲染和发布要求 Planner 9 / Snapshot 4。
- 地点变化会生成独立环境家族和完整场景组；同地点机位变化复用环境家族，第二场景仅继承风格参考，不复制第一场景构图。
- 计划、自然化快照、证明、预览批准、正式渲染和发布阶段均执行场景连续性与空间接地复检。
