# 纸片分镜全历史与素材复用改造原因说明

> 日期：2026-08-01
> 范围：纸片动画工作室（Paper Studio）
> 文档性质：改造原因与产品原则说明，不代表已经完成实现

## 1. 背景

纸片动画工作室已经具备分镜修订、生产版本、蓝图、独立素材槽位和素材版本等基础能力。在实际使用中，同一个分镜会经历多次调整，例如：

- 修改对白、旁白或镜头时长；
- 修正主体动作和转场节奏；
- 调整画面描述、场景或角色状态；
- 重新审核、替换或局部重生成某一张素材；
- 因连续性门禁失败而修改蓝图或动作计划。

这些调整不代表此前生成的所有图片都失去价值。大部分情况下，背景、角色、道具或部分状态图仍然可以继续使用。如果系统把每次修改都当作一套全新的生产任务，就会产生重复生图、重复审核、历史素材难以查找等问题。

因此，需要把“每个分镜的完整历史可见”和“历史素材可安全复用”提升为纸片工作室的基础能力，而不是只在单个素材槽位中临时保留几个候选版本。

## 2. 触发本次改造的直接问题

### 2.1 连续性错误缺少低成本修复路径

当系统提示“场景或主体切换过于突兀”时，原有流程只能阻止继续生产，没有提供能够保留当前生产成果的修复方式。

如果解决方式是：

1. 返回原分镜修改；
2. 保存为新的分镜修订；
3. 重新创建生产版本；
4. 重新生成全部素材；

那么一次原本只涉及转场时间或动作节奏的问题，可能导致已经生成并审核通过的图片再次消耗图片 API。这不符合用户预期，也不符合本地生产工具应有的成本控制原则。

正确方向应当是：优先在当前生产版本中修复蓝图或动作计划，保留未受影响的素材；确实需要新生产版本时，也必须先计算历史素材复用结果，只对发生实质变化的素材槽位重新报价。

### 2.2 历史图片虽然可能仍在，但用户无法按分镜完整查看

当前界面主要展示“当前生产镜头的当前素材槽位”，并在槽位内部展示该槽位的若干素材尝试版本。这种展示范围过窄，无法回答以下问题：

- 这个分镜以前一共创建过多少个生产版本？
- 每个生产版本分别生成过哪些背景、角色和道具图片？
- 哪一张图曾经被批准并进入正式视频？
- 哪些图只是被淘汰，哪些图因为技术门禁失败？
- 当前新版本能复用哪些旧图？
- 已经为这个分镜调用过多少次图片 API？

用户只能通过左侧生产版本列表逐个打开旧版本，再进入具体镜头和槽位查找图片。对于包含多个分镜、多个生产版本的项目，这种查找方式成本很高，也容易让用户误以为旧图已经丢失。

因此，每个分镜都必须拥有独立的“历史版本”入口，并以分镜为主线展示脚本修订、生产版本、蓝图版本和全部图片版本。

### 2.3 当前重新编译流程存在破坏历史关联的风险

当前生产计划持久化逻辑在重新编译镜头时，会删除旧的素材族和素材槽位，再创建一套新的记录。素材文件或素材版本记录可能仍然存在，但旧素材版本与原槽位、原计划之间的关系可能失去，最终表现为历史图片无法在界面中被正常查询和展示。

这说明问题不只是“缺少一个历史按钮”。如果底层仍然通过删除旧计划结构来完成重编译，历史界面得到的数据就不完整，后续素材复用也缺少可信依据。

本次改造必须先将生产计划、素材族和素材槽位改为不可变版本结构：新计划只能新增，旧计划只能标记为历史或已替代，不能物理删除。

### 2.4 当前跨生产版本复用条件过于严格

现有安全检查要求跨生产版本复用必须来自同一个纸片分镜修订。这个条件可以防止错误复用，但也会阻止大量实际上安全的复用场景。

例如：

- 只修改对白，不影响任何静态图片；
- 只延长镜头时长，不影响背景、角色和道具；
- 只修正转场缓动，不影响素材内容；
- 只调整字幕时间，不影响画面素材；
- 只修改主体运动轨迹，但主体身份和状态图未变化。

这些修改都会产生新的分镜修订，但不应该让全部历史图片失效。

因此，复用判断不能继续只比较“分镜修订 ID”，而应比较素材自身的视觉合同，包括主体身份、状态、场景、参考图、风格、画幅和素材用途等真正影响图片内容的字段。

### 2.5 当前图片报价没有扣除可复用的历史正式素材

现有报价流程可以识别当前槽位已经采用的素材，以及来自实体库的零调用素材，但没有把同一个分镜历史生产版本中的正式素材作为复用来源统一计算。

这会导致报价无法明确告诉用户：

- 需要多少个素材槽位；
- 其中多少张可以从历史版本复用；
- 多少张来自实体库；
- 多少张由本地程序派生；
- 最终真正需要调用图片 API 的数量。

如果费用预览没有先完成历史复用计算，用户就无法判断本次授权是否包含重复生成，也无法审核系统是否浪费图片 API。

## 3. 为什么不能只增加“历史版本”界面

只增加一个历史抽屉或图片列表，最多解决“看得见”的问题，不能解决以下根本问题：

- 重新编译仍可能破坏旧素材与计划的关系；
- 新生产版本仍然不能复用不同分镜修订中的安全素材；
- 费用报价仍然可能把可复用素材计算为新生成素材；
- 连续性修复仍然可能要求用户重新创建生产版本；
- 用户能看到旧图，却不能将其重新采用到当前槽位。

因此，本次改造必须同时覆盖四个层面：

1. 不可变历史数据；
2. 分镜级历史查看；
3. 基于视觉合同的安全复用；
4. 扣除复用结果后的图片 API 报价。

## 4. 改造目标

### 4.1 每个分镜拥有完整、独立的历史

历史范围至少包括：

- 所有分镜脚本修订；
- 所有包含该分镜的生产版本；
- 每个生产镜头的蓝图和动作计划版本；
- 每个素材槽位的全部图片版本；
- 已采用、已批准、已淘汰、已拒绝和生成失败的图片；
- 图片调用模型、调用时间、调用次数和审核结果；
- 历史素材被后续版本复用的来源与去向。

### 4.2 修复操作优先保留当前生产成果

转场时间、缓动、动作轨迹和遮挡关系等不改变静态素材内容的修复，应当在当前生产版本内完成。

修复前必须显示素材影响预览，例如：

```text
保留历史素材：4 张
新增素材槽位：0
失效素材：0
图片 API 调用：0 次
```

如果修复会新增场景、主体或状态，系统必须列出受影响的素材槽位，不能直接生成。

### 4.3 新生产版本只生成差异素材

当用户确实修改了分镜内容，需要创建新的生产版本时，系统应先执行素材复用预检。

典型结果应当是：

```text
所需素材：8 张
历史版本复用：4 张
实体库复用：2 张
本地派生：1 张
需要图片 API：1 张
```

只有最后无法复用的素材槽位进入付费授权。

### 4.4 所有复用都可解释、可审核、可追溯

历史素材不能因为“看起来相似”就被系统静默复用。系统必须记录并展示复用原因，例如：

- 同一角色形象版本、同一动作状态；
- 同一地点、时间、天气和构图参考；
- 同一视觉风格和画幅；
- 只修改了对白、声音或转场参数；
- 文件哈希和技术门禁仍然有效。

对于不能精确确认的素材，只能作为“可能可复用”候选交给用户审核，不能自动采用。

## 5. 必须遵守的产品原则

### 5.1 历史不可删除

- 重新分析不能删除旧计划、旧素材族或旧槽位；
- 新版本只能将旧版本标记为已替代；
- 历史图片文件只要仍被任意版本引用，就不能被清理；
- 已取消、失败或被淘汰的生产版本仍应可以查看。

### 5.2 零调用操作与付费操作必须分开

以下操作不得调用图片 API：

- 查看历史版本；
- 比较历史图片；
- 复用已批准且精确匹配的历史图片；
- 调整动作时间和转场缓动；
- 本地重新抠图、Mask 修正和程序化过渡；
- 重新执行连续性门禁。

只有明确缺少图片的素材槽位，才能进入图片 API 报价和授权。

### 5.3 先复用，再报价，再授权

正确顺序必须是：

1. 编译当前素材需求；
2. 匹配历史和实体库素材；
3. 展示复用清单；
4. 应用零调用复用；
5. 对剩余缺失槽位生成费用报价；
6. 用户明确确认；
7. 调用图片 API。

不能先按照全部槽位报价，再在生成过程中临时判断是否复用。

### 5.4 复用失败不能自动降级为付费生成

如果历史素材因为文件缺失、哈希不一致、主体身份变化或场景合同变化而无法复用，系统必须停止并说明原因。

不能在复用失败后自动调用图片 API补图。是否重新生成必须由用户再次决定。

## 6. 预期用户体验

### 6.1 分镜历史入口

每个分镜在创作页和生产页都显示“历史版本”入口。用户无需先查找生产版本，再逐个进入旧镜头。

历史页面按时间线组织：

```text
分镜修订 R3
  └─ 生产版本 R13
      ├─ 背景 V2（当前采用，可复用）
      ├─ 角色开始状态 V1（已批准，可复用）
      └─ 角色动作状态 V3（已淘汰）

分镜修订 R2
  └─ 生产版本 R09
      ├─ 背景 V1（已批准）
      └─ 角色开始状态 V1（已批准）
```

### 6.2 复用状态明确展示

每张历史图片应显示以下状态之一：

- 可直接复用（0 调用）；
- 需要人工确认；
- 不兼容，并显示具体原因；
- 文件缺失，不能复用；
- 已拒绝，仅供历史查看。

### 6.3 费用确认可核对

图片授权弹窗必须显示每个槽位的来源，而不只是显示一个总数量。

用户应能够核对：

- 哪些槽位使用历史图；
- 历史图来自哪个生产版本；
- 哪些槽位需要新生成；
- 每个新生成槽位最多允许调用几次图片 API。

## 7. 不改造的后果

如果维持现状，项目规模扩大后会持续出现以下问题：

- 用户无法确认旧图是否仍然存在；
- 修改非视觉内容也可能导致重新生图；
- 同一个角色、道具和背景被重复付费生成；
- 历史生产版本越来越多，但无法以分镜为单位查找；
- 费用报价无法解释哪些调用是必要的；
- 用户为了避免浪费费用，不敢修改分镜和修复连续性问题；
- 一旦重新编译破坏历史关联，后续再增加历史界面也无法完整恢复上下文。

这不仅是体验问题，也会直接影响用户对生产数据安全、费用控制和系统可信度的判断。

## 8. 改造完成的判断标准

至少满足以下条件，才能认为改造完成：

1. 一个分镜的所有脚本修订、生产版本和图片版本都可以在同一入口查看；
2. 重新编译生产计划后，旧素材族、旧槽位和旧图片仍然可查；
3. 只修改对白、时长或转场时，历史正式素材可以全部零调用复用；
4. 只更换背景时，角色和道具素材继续复用，只对背景报价；
5. 连续性修复可以保持当前生产版本和已生成图片不变；
6. 费用报价已经扣除历史复用、实体库复用和本地派生素材；
7. 未经最终授权，任何复用失败都不能触发图片 API；
8. 每次复用都有来源版本、兼容性报告和文件哈希记录；
9. 自动化测试能够证明“非视觉修改导致的图片 API 调用次数为 0”。

## 9. 结论

本次改造的核心不是增加一个历史图片列表，而是把纸片分镜从“当前生产状态界面”升级为“可追溯、可复用、可审核的版本化生产系统”。

用户已经支付成本生成并审核过的图片，应当成为项目长期可用的生产资产。任何脚本修改、转场修复或生产版本变化，都不能默认让这些资产失去价值，更不能在用户不知情的情况下重复消耗图片 API。

因此，完整历史、不可变关联、视觉合同复用和差异化报价必须作为同一次改造交付，不能拆成只有界面、没有底层保障的表面功能。
